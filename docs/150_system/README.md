# システムの現在像

> ここにある本文は、テンプレートの動かし方を示す作業記録アプリのサンプルです。新しい製品の開発を始める前に、`全体構造.md` と `データの構造.md` のサンプル本文を削除して製品の内容へ書き直し、`シーケンス`のサンプルファイルは削除して実際のシナリオから作り直してください。

このディレクトリは、複数のIssueと増分を経たシステム全体の現在像です。一回の変更だけを説明する増分とは役割を分けます。

```text
全体構造.md       動かす単位、責任、依存、外との境界
シーケンス/       シナリオを実現する現在の処理順と失敗時の戻り
データの構造.md   保存する実体、関係、所有、変わらない規則
```

増分で構造、処理順、データが変わるときは、同じPull Requestで該当文書を現在の姿へ書き換えます。過去の構造は残さず、Issue、Pull Request、Gitの履歴から追います。戻す費用が高い判断の理由だけは決定記録へ置きます。

シーケンスは要求の[シナリオ](../110_requirements/シナリオ/README.md)を参照します。処理単位から都合よく作らず、利用者の目的をシステムがどう実現するかを示します。同じ目的に入口が複数ある場合は、同じSCの中で入口別にシーケンス図を分けます。
