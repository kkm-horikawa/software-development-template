# シーケンス

シナリオをシステムがどう実現するか、複数の入口、利用手順、外部境界をまたぐ現在の処理順を一ファイルで示します。ファイル名は `SC-番号-目的.md` とし、対応する要求のシナリオへ相互にリンクします。

- [SC-001 作業を始める](SC-001-作業を始める.md)

一つのシナリオにHTTP、CLI、GUIなど複数の入口がある場合は、同じSCファイルの中で入口ごとにシーケンス図を分けます。入口ごとにSC番号を増やしません。目的、きっかけ、成功時保証が変わる場合だけ、要求側で別シナリオを作ってからシーケンスも分けます。

## 書く条件

- 順序を間違えると一部だけ成功する
- 判定や処理が複数の責任または配備単位へ分かれる
- 条件によって呼ぶ相手や返す結果が変わる
- 一回の要求と応答だけでは利用者の目的まで説明できない

単純な受け渡しをAPI一覧から写すだけなら書きません。シーケンスは一つの増分の実装計画ではなく、増分をまたいで生きるシナリオの現在像です。体験や処理順が変わる増分で同じファイルを更新します。
