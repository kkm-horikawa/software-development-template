# SC-001 作業を始めるシーケンス

対応する体験: [SC-001 作業を始める](../../110_requirements/シナリオ/SC-001-作業を始める/README.md)

## HTTPから始める

```mermaid
sequenceDiagram
    actor User as 作業を記録する人
    participant HTTP as FastAPI入口
    participant Usecase as StartActivity
    participant Domain as Activity
    participant Repository as 保存境界
    participant SQLite

    User->>HTTP: POST /activities {title}
    HTTP->>Usecase: 作業名を渡す
    Usecase->>Domain: 作業名を作る
    alt 作業名が空
        Domain-->>HTTP: 作業名が空という理由
        HTTP-->>User: 422、保存しない
    else 作業名が有効
        Usecase->>Domain: 識別子と開始時刻で作業を始める
        Usecase->>Repository: 作業を保存する
        Repository->>SQLite: INSERT activities
        SQLite-->>Repository: 保存完了
        Repository-->>Usecase: 保存完了
        Usecase-->>HTTP: 開始した作業
        HTTP-->>User: 201、識別子、作業名、開始時刻
    end
```

作業名の規則はDomain、作業開始の順序はUsecase、HTTP状態への変換はFastAPI入口、永続化はSQLAlchemyの保存実装が受け持ちます。保存が完了する前に201を返しません。

## Go CLIから始める

```mermaid
sequenceDiagram
    actor User as 作業を記録する人
    participant CLI as Go CLI
    participant ClientUsecase as GoのStartWork
    participant Gateway as ActivityGateway
    participant API as FastAPI
    participant BackendUsecase as PythonのStartActivity
    participant SQLite

    User->>CLI: worklog start 設計を書く
    CLI->>ClientUsecase: 作業名を渡す
    ClientUsecase->>Gateway: 作業開始を依頼する
    Gateway->>API: POST /activities {title}
    API->>BackendUsecase: 作業名を渡す
    BackendUsecase->>SQLite: SQLAlchemyを通して保存
    SQLite-->>BackendUsecase: 保存完了
    BackendUsecase-->>API: 開始した作業
    API-->>Gateway: 201、識別子、作業名、開始時刻
    Gateway-->>ClientUsecase: 作業の型
    ClientUsecase-->>CLI: 開始した作業
    CLI-->>User: 開始: 設計を書く
```

GoクライアントはPythonの型とSQLiteを知りません。`contracts/worklog-api.openapi.json` に公開した要求と応答だけを境にします。通信または契約の読み取りに失敗した場合、CLIは開始したと表示しません。

要求を送った後に応答だけ失われた場合、CLIからは保存の有無を確定できません。現在は結果不明として失敗を返し、自動再試行しません。再試行しても二重登録しない仕組みは、識別子または結果照会を扱う後続のシナリオと増分で決めます。
