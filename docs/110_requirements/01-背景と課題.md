# 背景と課題

> 作業記録アプリのサンプルです。新しい製品では、最初のIssueへ着手する前に本文を削除し、観測した事実と本人の判断から書き直してください。

## 背景

一人の開発者が複数の案件を行き来している。作業を始めた時刻と内容は記憶や各サービスの履歴に散り、あとから一日の実績を復元している。利用する入口はCLIだけでなく、将来Webやモバイルへ増える可能性がある。

## PB-001: 始めた作業をあとから正確に追えない

作業名と開始時刻が一つの保存先へ残らず、何をいつ始めたかを記憶から復元している。空の作業名が残ると、記録があっても内容を判断できない。

## PB-002: 利用先を増やすとバックエンドの内部実装へ結び付きやすい

利用先が通信の約束ではなくバックエンドのコードを直接使うと、言語や配布周期を独立させられない。新しい利用先を加えるたびに、バックエンドと同時に変更する必要が生じる。
