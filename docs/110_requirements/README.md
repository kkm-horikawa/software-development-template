# 要求の正典

> ここにある本文は、テンプレートの動かし方を示す作業記録アプリのサンプルです。新しい製品の開発を始める前に、`01`から`04`のサンプル本文を削除して製品の内容へ書き直し、`シナリオ`のサンプルファイルは削除して実際の目的ごとに作り直してください。サンプルへ製品の要求を継ぎ足してはいけません。

このディレクトリは、複数のIssueと増分をまたいで生きる「製品が今なぜ必要で、誰へ何を提供し、何を満たすか」の正典です。

```text
01-背景と課題.md          なぜ作るのか、今何が起きているか
02-利用者とシナリオ.md    関係する立場と、目的ごとのシナリオへの入口
シナリオ/                 利用者が目的を達成する一連の体験
03-要求.md                課題を解くために必要な状態
04-受入基準.md            要求を満たしたと外から判定できる状態
```

シナリオは画面や機能の一覧ではなく、一人の利用者が一つの目的を達成するまでの旅ごとに一ファイルで置きます。増分で体験を追加、変更、削除するときは、同じ変更で該当シナリオと要求、受入基準を現在の姿へ更新します。過去の姿はGitとPull Requestが持ちます。

既定ブランチのシナリオは、今提供できる体験だけを表します。まだ実現していない案はIssueに置き、実装する増分のブランチでシナリオと要求を一緒に更新します。途中の案を既定ブランチへ先に置きません。

シナリオ一覧を読めば、製品が今提供する体験の全体が分かります。一覧に無い体験は、少なくとも現在の正典にはありません。ただし「意識して提供しないこと」を約束する必要がある場合は、不在だけに頼らず該当シナリオか要求へ明記します。見落としと判断を区別するためです。

`PB`、`SC`、`REQ`、`AC` はこの正典の中で一度だけ使う三桁の番号です。既存の最大値の次を、実際に項目を追加するときに割り当てます。削除した番号は別の意味へ使い回しません。
