# 要求

> 本文は作業記録アプリのサンプルです。新しい製品を始める前に背景・利用者・要求・横断条件を書き直し、サンプルのシナリオ・受入例・増分は実際のものへ置き換えてください。

背景はなぜ必要か、利用者は誰のためか、要求は製品全体の範囲を持ちます。目的ごとの[シナリオ](シナリオ/README.md)が、現在の体験と成功・失敗の条件を持ちます。

シナリオのREADMEと受入例の一覧は同じディレクトリへ置きます。受入例の具体的な値はテストのCSV等を正本にし、文書へ写しません。横断的な品質条件だけは `04-横断的な受入条件.md` に置きます。

現在像の更新は、実際にその意味が変わる場所だけに閉じます。既定ブランチには実装済みの体験を置き、未実装の案はIssueで扱います。過去の姿はGitとPRから確認します。

識別子は目的を示すSC、個別ケースを示すEX、変更を示すIssue番号付きINCに絞ります。SCは目的を追加するとき、EXはケースを追加するときに採番し、削除した番号を別の意味へ使い回しません。本文の背景・要求・条件それぞれに連鎖する番号は不要です。
