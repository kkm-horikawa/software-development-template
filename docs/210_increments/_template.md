# INC-<Issue番号> 短い名前

対応Issue: #<Issue番号>

> ファイル名は `INC-<Issue番号>.md`。一つのIssueを複数へ分けるときだけ `INC-<Issue番号>-<枝番号>.md`。下の `増分キー` はファイル名の `INC-` より後ろと同じにする。

増分キー: <Issue番号またはIssue番号-枝番号>

## 変える体験

誰が、どの入口で、何をして、何が起きるようにするかを書く。

## 外から見える振る舞いと確認

### SPEC-<増分キー>-01: 振る舞い [AC-SC番号-番号]

入力、結果、状態変化を書く。

### ST-<増分キー>-01: システムテスト [SPEC-<増分キー>-01]

実際の入口へ何を渡し、何を観測すれば合格かを書く。

- 実行物: `テストファイル::test_sc番号_ex番号_名前`

## 設計上の境界と確認

### AD-<増分キー>-01: 境界 [SPEC-<増分キー>-01]

変更をどこへ閉じ込め、依存をどちらへ向けるかを書く。

### IT-<増分キー>-01: 結合テスト [AD-<増分キー>-01]

どの実物同士をつなぎ、何を観測すれば境界が正しいと分かるかを書く。

- 実行物: `テストファイル::テスト名`

## 実装の段

入口から同じ粒度で並ぶ処理と、次に一段詳しくなる処理を書く。

```text
入口.run
  → 段A
  → 段B
  → 段C
```

## 対象外

要求を決める時点で意識して作らないものを書く。未達や未確認をここへ移さない。

## 現在像の更新先

この増分で更新する `110_requirements` のシナリオ・要求・受入例・横断的な受入条件と、`150_system` の全体構造・シーケンス・データ構造を書く。更新しない文書は、影響が無いと判断した理由を書く。
