# 増分

> INC-1とINC-3はサンプルです。新しい製品では削除して実際のIssueから作り直してください。

Issue番号が決まったら[_template.md](_template.md)を `INC-<Issue番号>.md` として写します。一つのIssueを分けて届ける必要がある場合だけ `INC-42-1.md` のように枝番号を付けます。

書くのは今回の変更範囲、設計理由、その境界をどう確かめるかです。既存の仕様やCSVの入力・期待結果は写しません。SPEC・AC・ST・ITの連鎖台帳を増分へ追加する必要はありません。必要な確認に番号を付ける場合も増分内だけで扱い、Issue作成時に予約しません。

作業中の記述は実装に合わせて直します。完了後は当時の変更記録として残し、後続のテスト改名や機能削除には追従させません。当時の実装と結果は対応PRの差分・コミットで確認します。検査はファイル名とIssue番号を照合し、過去の記録が現在のテストを参照し続けることを要求しません。
